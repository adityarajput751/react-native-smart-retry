# SmartRetry example

Demonstrates `react-native-smart-retry`'s offline queue end-to-end, using a
built-in mock API (`src/api/mockApi.ts`) so it runs with **no real backend**.

## What it shows

- **Device network**: live online/offline status from `SmartRetry.isOnline()` / `onNetworkChange`.
- **Simulate API offline** switch: forces every mock API call to fail with a
  network error, independent of your simulator/device's real connectivity —
  the easiest way to demonstrate queueing without touching airplane mode.
- **Create API Request**: issues a `POST /attendance` via `SmartRetry.request()`
  with `queue: true`.
- **Process Queue**: manually triggers `SmartRetry.processQueue()`.
- **Clear Queue**: wipes all persisted requests.
- A live list of queued requests (id, URL, method, status, created time, retry count).

## Running it

This folder contains the app's source only (`App.tsx`, screens, mock API) —
it is meant to be dropped into a React Native host project rather than run
standalone, since a runnable RN app also needs native iOS/Android project
files generated by the RN CLI or Expo.

1. Create a host app next to this package, e.g.:
   ```sh
   npx react-native init SmartRetryExample
   ```
2. Copy `App.tsx`, `index.js`, and `src/` from this folder into it, replacing the generated versions.
3. Install dependencies (from the host app's root):
   ```sh
   npm install @react-native-async-storage/async-storage @react-native-community/netinfo
   npm install ../react-native-smart-retry
   ```
4. Run it:
   ```sh
   npx react-native run-ios     # or run-android
   ```

Or, with Expo:

```sh
npx create-expo-app SmartRetryExample
# copy App.tsx and src/ in, then:
npx expo install @react-native-async-storage/async-storage @react-native-community/netinfo
npm install ../react-native-smart-retry
npx expo start
```

## Try the offline flow

1. Tap **Create API Request** a few times — with the API online, they succeed immediately and the queue stays empty.
2. Flip **Simulate API offline** on, then tap **Create API Request** again — it queues instead (`status: 'queued'`), and shows up in the list below with `status: pending`.
3. Flip **Simulate API offline** off, then tap **Process Queue** — the queued request replays, succeeds, and disappears from the list.
4. Force-quit and reopen the app while a request is still queued — it's still there, proving the queue survives app restarts.
